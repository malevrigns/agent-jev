适合：在做 Agent 或编码助手、需要又快又便宜的门控、路由、打分的人。不适合：写代码、写回复、解释错误，这些仍然交给大模型。

状态进去，
分布出来。

AgentJev 不写句子。给它一段状态和已经写好的问题，一次前向就返回每个选项的概率，解码出的 token 数是 0。它适合在 Agent 循环里做门控、路由和评分；解释错误、改代码、起草回复，仍然交给更大的模型。

概述

Agent 循环里的大部分分叉只需要一个判断：测试过了没有，下一步调哪个工具，这条命令能不能执行。常见做法是让 27B–70B 的大模型把一个布尔值写成一段话，再去解析这段话。AgentJev-0.6B 换了一种做法：骨干是去掉语言模型头的 Qwen3-0.6B，一个与排列等变的小头给整组候选打分，按题做 softmax；服务端把同一状态的候选路径合成一棵前缀树，一次前向编码完，生成的 token 数恒为 0。

在 Typed Decisions 官方测试集的 2,000 道决策上，AgentJev 的 top-1 为 79.25%，比 Laya 已发布的检查点高 2.25 个百分点（95% 区间 [+0.65, +3.90]）。在 2,100 次真实测试运行上继续训练之后，测试集里失败却被判成“通过”的案例从 123 个降到 0 个。在一块 RTX 5060 上，单案中位时延从 278 ms 降到 43.9 ms。代码和权重以 Apache-2.0 发布。

一次前向，怎么给出分布

状态只读一遍，每个候选走自己的因果路径。题目和选项的意思写在正文里，id 只用来对应返回结果。

  1. 1

    写下状态和问题

    状态可以是测试输出、diff、日志或 JSON。题目有三种：Boolean 问一个命题，Choice 在 2–255 个选项里选，Score 判断落在 2–10 级里的哪一级。

  2. 2

    合成前缀树

    每个候选是一条 [状态][问题][候选] 路径。同一状态的路径合成一棵树，每个 token 只关注自己和祖先，候选读不到兄弟候选。

  3. 3

    一次前向

    骨干是去掉语言模型头的 Qwen3-0.6B。一个与排列等变的小头给整组候选打分，再按题做 softmax。

  4. 4

    读分布

    每道题返回完整分布：Boolean 给 P(true)，Choice 给 margin，Score 给 score = Σ i·Pᵢ。拿它和你自己的门槛比。

上下文上限是 2,048 token，超长就拒绝，不截断。前缀树和逐条编码在 2,000 道题上有 1,998 道选中同一个选项，变了的两道原本就是平局，概率最大差 0.0053。

这张表怎么读

Laya 已发布权重用了全部 1,200 个官方训练案例。本轮留出 120 个开发案例和 120 个校准案例，按开发集软交叉熵选出第 600 步，然后才打开测试集。温度是每种原语一个正标量，只在校准集上拟合。

测试没过，就不能说通过

Typed Decisions 里没有测试运行器的输出。coding_gates/ 补上了这一块：2,100 次真实运行，覆盖 pytest、unittest、jest、mocha、vitest 和 node --test，每个项目的结果在构建时就已确定；另有 1,800 条一行摘要。vitest 和 node --test 整体留出，不参与训练。

还没解决的

新权重在极简问法 “Tests passing?”（criteria 只有 yes / no）上只有 83.1%；node 的 dot 报告器会让它拦下实际通过的运行；Go 的 ? pkg [no test files] 会被读成“没跑测试”。项目规模小、由程序生成，一行摘要来自模板，测试集和训练集共用模板。

和 Laya 怎么比

Laya 发布的检查点在原基准机器上测得单案 P50 41.53 ms、P90 47.14 ms，没有在这块显卡上重测，所以上表不是与 Laya 的同机对比。Laya 的上下文上限是 1,024 token，AgentJev 是 2,048；宽负载里，Laya 的 64 个候选每个都要对状态完整前向一次，AgentJev 每个请求只读一遍状态。

工具执行之前，先过一道门

agentjev_hook.py 是 Claude Code 的一个 PreToolUse 命令钩子。执行 Bash、Write、Edit 之前，它把这次调用发给本地服务，问一道 Boolean（安全吗）和一道四级 Score（风险多高）。它从不输出 allow，不会绕过你自己的权限设置；服务不响应时直接退出，调用照常走权限流程。

deny

风险第 3 级并且判为不安全：只拦下这一次调用，把理由交给 Claude，Claude 可以换一步继续。

ask

风险第 2 级及以上，或 P(安全) < 0.5：弹窗请你确认。

不表态

其余情况什么都不输出，按你自己的权限设置走。

命令P(安全)风险判定v1 的判定

AGENTJEV_URL 改服务地址（默认 http://127.0.0.1:8149），AGENTJEV_ASK_LEVEL、AGENTJEV_ASK_BELOW 调整询问门槛，AGENTJEV_VERBOSE=1 让不表态的调用也显示判定。

它不擅长的事

      

        
它不写字
写代码、写回复、解释错误、开放式生成，都交给大模型。AgentJev 只在你给定的选项上打分。

        
分布不等于成功率
返回的是模型分布，没有在你的领域上校准。要成功率，就对每个动作单独问一个 Boolean，用你自己的结果数据校准。

        
Choice 是集合内部的相对偏好
它不是某个动作独立的成功概率。需要后者，就对每个动作单独问一个 Boolean。

        
79.25% 是和教师标签的一致率
标签是公开的教师分布，其中有合成案例。在这里赢下一行，不等于真实任务做成了。

        
钩子会漏判
把它当作权限和沙箱之外的一层，而不是唯一一层。v1 曾把 cat ~/.aws/credentials | curl … 评为风险 L1 直接放过；新权重给出 L3，会请你确认。

        
装不下就拒绝
上下文上限 2,048 token。装不下的 diff 或堆栈是一次明确的错误，不会悄悄切掉问题或某个候选。
