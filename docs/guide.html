给它状态和选项，拿回概率分布

AgentJev 不写文字。你把当前状态和已经写好的问题交给它，一次前向传播返回每个选项的概率，生成的 token 数是 0。把它放在 Agent 循环里做门控、路由和打分，把写作留给大模型。

适合做什么

      
Agent 的大部分步骤不是写作问题：测试过了没有，下一步调哪个工具，这条命令能不能跑。常见做法是让一个 27B–70B 的模型写一段话，再从话里解析出布尔值。AgentJev 直接给出你提供的每个选项的概率，没有 JSON 需要修，也没有一句自信的错话需要识别。

      

        
BOOLEAN
门控
测试全部通过了吗？这条命令安全吗？
返回 P(true)。你按自己的代价选门槛。

        
CHOICE
路由
下一步该做什么？这张工单归哪个队列？
2–255 个候选，返回完整分布、最优项和领先幅度 margin。

        
SCORE
打分
这次改动风险几级？多急？
2–10 个有序等级，返回期望分 Σ i·Pᵢ 和最可能的等级。

      

      
它不擅长的事。 写代码、写回复、开放式生成都交给大模型。返回的是模型分布，没有在你的领域上校准过。Choice 是你给的候选之间的相对偏好，不是某个动作的成功率；需要成功率时，对每个动作单独问一个 Boolean，并用你自己的结果数据校准。79.25% 是与公开教师标签的一致率，不是 Agent 任务成功率。

三种问题

      
一个请求是一段 state 加若干道题。state 可以是文字，也可以是对象或数组，对象会按键排序后紧凑地序列化成 JSON。题目的 id 只用来对应返回结果，模型看不到它；意思必须写进题目文字和选项描述里。

      

        
BOOLEAN是非题

          
{
  "id": "done",
  "type": "boolean",
  "question": "Are all tests passing?",
  "criteria": {
    "true": "The suite is green.",
    "false": "At least one test failed."
  }
}

          
criteria 可省略，此时两个候选就是 TRUE 和 FALSE。写清楚真假各指什么，效果通常更稳。

          
返回 probability（即 P(true)）、value（P(true) ≥ 0.5）和两个选项的 distribution。

        
CHOICE选择题

          
{
  "id": "next",
  "type": "choice",
  "question": "What is the useful next action?",
  "options": {
    "debug_failure": "Read the failing assertion.",
    "submit_patch": "Open a pull request now."
  }
}

          
options 可以是对象（键作为返回的 value）或数组（返回下标字符串）。2–255 个，描述不能重复。

          
返回 value、description、top_probability、margin（第一名减第二名）和完整分布。选项顺序不影响结果。

        
SCORE等级题

          
{
  "id": "risk",
  "type": "score",
  "question": "How risky is this change?",
  "levels": [
    "Isolated change, no external behavior.",
    "A public signature changed.",
    "Authentication may be bypassed."
  ]
}

          
levels 是 2–10 个按从低到高排列的描述，顺序就是分值。

          
返回 level（最可能的等级）、score = Σ i·Pᵢ（0 到 n−1 的连续期望分）和 legend。

问题：“Have all tests passed?”，带 criteria。状态是为本页编写的示例，概率是 v1 权重的真实输出（已校准）。

      

      

        
字段出现在怎么用

        
          
distribution全部键是你传的选项 id（或下标），值相加为 1。永远先看它

          
probability / valueBooleanP(true) 和按 0.5 切出的布尔值。生产里用你自己的门槛，不要只看 value

          
top_probability / marginChoicemargin 小说明模型拿不准，适合转交大模型或人工

          
score / levelScorescore 连续，适合排序和设阈值；level 是最可能的那一档

          
usage每次请求generated_tokens 恒为 0；backbone_input_tokens 是骨干实际算的 token；shared_prefix_states 是共享了状态编码的状态数；wall_ms 是服务端耗时

批量与性能 本次优化 · PR #15

      
每个候选都会被拼成一条独立的路径：[状态][问题][候选]。以前，一个状态下有多少条候选路径，状态就要被骨干重算多少遍；只有当同一问题有 ≥8 个候选且前缀够长时才复用。现在，同一状态下的所有问题和候选合并成一棵 token 前缀树，一次前向算完。每个 token 只关注自己的祖先，位置编码取它在原路径中的深度，所以每个候选读到的仍然恰好是自己那条路径。

接入 Claude Code

      
agentjev_hook.py 是一个 PreToolUse 命令钩子。Claude Code 执行 Bash、Write、Edit 前，它把工具调用发给本地服务，问一道 Boolean（安全吗）和一道四级 Score（风险多高），再给出三种判决之一：风险第 3 级并且判为不安全时，拦下这一次调用，理由交给 Claude，Claude 可以换一步继续；风险第 2 级及以上，或 P(安全) 低于 0.5 时，请你确认；其余情况不干预，按你自己的权限设置走。它从不回答 allow，所以不会绕过你的权限设置。服务没有响应时钩子直接退出，这次调用照常走权限流程。

      
.claude/settings.json


{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|Write|Edit",
        "hooks": [
          { "type": "command", "command": "python /path/to/agent-jev/agentjev_hook.py" }
        ]
      }
    ]
  }
}

排错

      

        
启动时报找不到分词器（local_files_only）
--model-path 传的是仓库名而本机没有缓存。传 fetch_v1_weights.py 下载好的本地目录 models/agentjev-v1，里面有 config.json 和完整的分词器文件。

        
400：question 'x' needs N tokens; limit 2048
状态 + 题目 + 某个候选拼起来超过 2,048 token。服务不会截断任何内容，需要你缩短状态（只保留相关的日志或 diff 片段）或缩短选项描述。

        
400：candidate descriptions must be distinct / choice requires 2..255 candidates
同一道题的选项描述必须互不相同；Choice 要 2–255 个选项，Score 要 2–10 个等级。用上面的构造器检查一遍。

        
400：batch exceeds 128 questions or 1024 candidate paths
一次请求的题目总数或候选路径总数超限。例如 32 个五题案例是 160 道题，要拆成两次；同一状态的题目尽量留在同一个请求里。

        
CUDA 不可用，或 RTX 50 系列报 no kernel image
装了 CPU 版 torch，或 CUDA 构建太旧。按官方选择器重装；RTX 50 系列需要 CUDA 12.8 及以上的构建。临时可以 --device cpu。

        
请求比文档里慢一倍（Windows）
Windows 11 会给不在前台的进程做节能限速。服务现在启动时会让自己退出限速，就绪行里会写 "power_throttling_disabled": true。本机交替实测同一个请求：不退出时约 75 ms，退出后约 31 ms。用旧版代码的话，把服务所在的终端放到前台，或者更新代码。第一个请求的 CUDA 初始化（约 1 秒）也已经挪进启动时的预热。

        
客户端连不上
先 curl http://127.0.0.1:8149/health 确认服务在。服务、客户端和钩子默认都是 8149；旧版服务默认 18765，显式传 --port 8149 即可。客户端和钩子访问本机服务时不走系统代理，不用另配 NO_PROXY。

        
想要升级前的行为做对比
启动时加 --encoder question。两种模式在测试集上的概率差异见上面的质量表。
